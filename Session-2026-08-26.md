### 1. The endpoint

Two routes, importing none of the review core:

- **`GET /`** — health, `{"service": "co-lectr", "status": "ok"}`, no credentials. The one line a
  deploy is verified against.
- **`POST /webhook`** — the raw body is HMAC-checked against `GITHUB_WEBHOOK_SECRET` with a
  constant-time compare *before any field is read*. A `ping` is answered, a reviewable pull-request
  event (`opened` / `synchronize` / `reopened`) is routed to a `ReviewTarget{repo, pr, sha}`, and
  anything else — a wrong event, an action we skip, a malformed payload — is acknowledged with a 2xx
  and dropped, because GitHub retries on anything else.

With no secret set, every POST is refused rather than waved through: an unsigned webhook is an open
door to a model that influences a grade. The `ReviewTarget` the receiver produces is the seam step 5
hangs off.

### 2. The container

The repo *is* the `co_lectr` package and every import is `co_lectr.*`, so the Dockerfile copies the
code into a directory of that name with its parent on the path — the same reason the README clones into
`co_lectr/`. gunicorn is imported by nothing in the code, so it lives in the Dockerfile, not in
requirements. Dependencies install off `requirements.txt` alone in an earlier layer, so a code change
does not rebuild them.

### 3. The README

A webhook-service section (the two routes as a table), a `gcloud run deploy --source .` walkthrough
through to pointing a GitHub webhook at `/webhook` and confirming the `ping`, updated config and status
tables, and the architecture diagram redrawn: the Cloud Run node is now **solid** (it exists and is
tested), but its edges stay **dashed** — wiring GitHub to deliver PRs and having the endpoint run the
review is the delivery path still in progress. Nothing is claimed that does not run.

## Decisions taken

| # | Decision | Rationale |
|---|---|---|
| 1 | Webhook validates and routes only; no fetch/review this session | Keeps the receiver free of the review core, cheap to start and testable offline. Fetch→review→comment is step 5 |
| 2 | `web.py` imports nothing from the review core | The endpoint's job is narrow; coupling it to ADK/Gemini/Firestore would make it heavier and harder to reason about |
| 3 | No secret configured ⇒ refuse every POST | A security-first project cannot default an unauthenticated webhook to open |
| 4 | `flask` in `requirements.txt`, `gunicorn` in the Dockerfile | requirements lists what the code imports; the Dockerfile adds the server that runs it. gunicorn is imported by nothing and does not run on the Windows dev box |
| 5 | The three E501s in the new files were left | The repo's own code freely exceeds 88 chars (up to 118; 85 pre-existing E501s). `E,F,B` is what *student* code is linted with, not ours — matching the surrounding style wins |
