## 2. Step 5 — the delivery path (code)

The seam that turns the front door into the product. Written to reuse the review core unchanged; only the
fetch and the post are new.

| File | |
|---|---|
| `github.py` (new) | Thin GitHub client on `urllib` — no new dependency. `fetch_source` (tarball at `sha`, extracted with tarfile's `data` filter so a member can't escape the dir) and `post_comment`. |
| `pipeline.py` (new) | `run_review`: fetch head → `analyse` (layer 1) → `review` (layer 2) → one PR comment. Idempotent on `reviews/{repo}#{pr}#{sha}`. `format_comment` and `config_from_env`. |
| `web.py` | On a reviewable PR *with* `GITHUB_TOKEN` set, dispatches the review on a background thread and returns `202` at once; the review core is imported lazily inside the worker. Without a token, the old acknowledge-only behaviour stands. |
| `tests/test_github.py`, `tests/test_pipeline.py` (new) | 7 tests, fetch and model faked — no network, no Gemini. |
| `tests/test_web.py` | +1: a reviewable PR dispatches the review when a token is configured. |
| `README.md` | New env vars, the delivery-path section, honest status (`🔨` — built and unit-tested, not yet live). |

### MVP choices (agreed this session)

| Decision | Rationale |
|---|---|
| PAT auth, not a GitHub App | Enough for the pilot on a throwaway repo; a GitHub App slots behind the same two `github.py` methods later. Four days left. |
| One consolidated PR comment, not inline | Line-anchored review comments only take lines inside the PR diff; our findings anchor anywhere in the file. A single comment always posts. Inline is a later refinement. |
| Config from env vars | `COLECTR_CHAPTERS` / `COLECTR_REQUIRE` / `COLECTR_MILESTONE` on the service — one setting for the pilot, no class-record read to build yet. |
| Background thread + `202` | A Gemini call takes seconds; GitHub's delivery times out at ~10s. Ack fast, review off-thread. Needs `--no-cpu-throttling` on redeploy. |
| Idempotent on the commit sha | GitHub retries a slow delivery. `reviews/{repo}#{pr}#{sha}` stops a second review or a duplicate comment. |
| `pytest` and Firestore **off by default** | `pytest` executes student code; both are opt-in (`COLECTR_RUN_TESTS=1`, `COLECTR_FIRESTORE=1`) so the first live run is fetch → analyse → review → comment, nothing more. |
